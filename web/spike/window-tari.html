AgentPay — connect your own wallet (window.tari spike)

The same open/pay instruction mapping as flows A/B, but signed and submitted by the user's own wallet through the window.tari provider — the Tari Universe web wallet (universe.tari.mw). No backend, no user-run walletd, no browser-held key; every transaction is approved in the wallet's own popup.

Blockers before this round-trips on esmeralda (all current as of 2026-11-07):
  1. No funds. The 0.49.2 reset wiped esmeralda — the Caravel faucet is gone and the walletd faucet is empty. A fresh account can't pay a fee until funded (L1-burn is the only documented route).
  2. Template gone. The published AgentBudget template was wiped by the reset; it must be republished on 0.49.2 and its new address put in the field below.
  3. Universe loads dApps in a cross-origin iframe. This page gets window.tari only when opened inside universe.tari.mw (a plain localhost tab gets nothing). The dev server must send Content-Security-Policy: frame-ancestors 'self' https://universe.tari.mw;, and how to point Universe at a localhost dev URL is not yet confirmed.
Deps are on ootle.ts 0.13 / Ootle 0.49.2 (done). A few VERIFY: points in the source still need a live-wallet check.
